## 第 1 阶段：基线与绑定

### 文件范围

修改根 `package.json`、锁文件，归并共享协议接入所需的 `src/protocol` 文件及现有协议回归测试。共享包源码和 vendor 产物沿用已有工作区，不重新提取。

新增：

- `src/cloudSync/cloudSyncTypes.ts`：服务信息、绑定配置及错误类型。
- `src/cloudSync/cloudBinding.ts`：绑定、恢复、替换和解除绑定。
- `src/cloudSync/cloudSyncApi.ts`：专用原生命令的类型化调用。
- `src-tauri/src/cloud_sync.rs`：绑定地址验证、服务信息和允许路径的请求。
- `src-tauri/src/cloud_credentials.rs`：Windows 系统凭证存储。
- `tests/cloudBinding.test.mjs`：绑定生命周期测试。

修改 `src-tauri/Cargo.toml`、`src-tauri/src/lib.rs` 及必要的主窗口能力配置。复用现有 reqwest，不开放通用 HTTP 域名权限。正式设置界面在第 6 阶段加入。

### 绑定与请求契约

绑定配置包含 `binding_id`、规范化 `base_url`、已确认 `server_id`、`credential_ref`、服务/API/协议版本、保留策略及最近核验时间。令牌仅进入系统凭证存储，不进入 SQLite、普通配置、日志或导出。B 站登录凭证不参与云端同步请求。

一个活动绑定，旧来源记录保留。公网使用 HTTPS；本机开发支持回环地址 HTTP。原生请求只访问绑定地址和明确支持的 API 路径，禁止自动跟随重定向。资源请求只能使用服务端相对资源路径，不接收任意外部 URL。

绑定前核验 `/info`：API 主版本为 1、数据库可用、协议版本在已验证支持范围。当前协议支持基线为 0.1.3；不因服务版本号相同就推断兼容。后续响应中的 `server_id` 必须与绑定一致。

身份变化、API／协议不兼容以及任一路径的 401 均暂停绑定，并拒绝提交已准备页面。用户确认新服务器后创建新来源并从 0 开始，不沿用旧游标，不删除旧档案。

### 生命周期与失败

1. 验证候选服务器和令牌。
2. 以新 `binding_id` 写入系统凭证。
3. 保存配置、切换活动绑定。
4. 替换成功后移除旧凭证。

非秘密配置直接保存至 cloud_binding。配置保存失败保留旧绑定并清理新凭证。新配置已保存但旧凭证清理失败时，新绑定保持可用，并返回需要清理旧凭证的提示。重启缺少凭证时保留配置和进度，暂停同步并要求重新输入，不退回普通文件存储。

解除绑定停止新请求、移除活动配置及凭证，不删除档案、来源记录或游标。解除绑定过程中凭证删除失败不得报告完全解除成功。

### 验收

共享协议回归测试、客户端测试和构建通过。覆盖绑定替换失败、系统凭证写入/读取/删除失败、重启恢复、API 不兼容、server_id 变化及重定向。确认请求不携带 B 站 Cookie，普通配置和导出不含令牌。原生凭证生命周期用本地合成凭证验证，不使用真实令牌。

## 第 2 阶段：SQLite 来源与双游标

### 文件范围

修改 `src/archive/archiveSchema.ts`、`archiveWriter.ts`、`archiveRepository.ts`、`archiveRuntime.ts`、`archiveTransfer.ts` 和 `src-tauri/src/archive_database.rs`。

新增 `src/cloudSync/cloudSyncRepository.ts`、`cloudSyncCommit.ts`、`cloudSyncCursor.ts`、`src-tauri/src/cloud_sync_database.rs` 及对应测试。新增提交命令复用既有写连接与互斥锁，不另建数据库。

### 模型

| 表 | 主键及内容 |
| --- | --- |
| cloud_binding | binding_id；绑定配置，无令牌 |
| cloud_room_state | server_id + room_id；event_cursor、metadata_cursor、解析版本及上下文检查点 |
| cloud_source_record | server_id + room_id + server_sequence；接收时间、命令、可空服务端场次、快照引用、解析版本及状态 |
| cloud_source_output | 来源身份 + 输出序号；本地 event_key 及本地删除标记 |
| cloud_metadata_record | server_id + room_id + revision；元数据修订及应用状态 |
| cloud_range_evidence | 房间来源 + 区间种类 + 原起止边界；原因及观察修订 |

来源记录支持零个或多个输出。解析状态区分成功、有意无输出、未知命令、解析失败。输出关联在本地事件删除后仍保留来源身份和删除标记，不能级联删除来源收据。

既有 `archive_source`、`archive_event_source` 继续表达档案来源。快照内容、场次映射和封面表在其消费阶段加入。

所有云端房间号、UID、序号及修订号保持规范十进制字符串，不经过不安全的 Number 转换。现有本地数字房间字段写入前校验精度，无法准确表示时暂停该房间，禁止截断。十进制比较使用 BigInt 或等价精确比较，不能采用普通字符串字典序。

本地不长期存储完整原始命令副本，保留来源索引、状态及必要解析上下文。服务器原文过期后不能承诺重解析。

### 提交事务

专用原生提交命令在事务内核对绑定来源和预期旧游标，分配事件序号，写来源记录、输出、来源关联、搜索索引及统计，保存解析上下文，然后推进对应游标。任一步失败全部回滚。旧游标不匹配时不写入，调用方重新读取进度。

现有通用批量事务不能在事务内读取和判断游标，因此不能用提交后检查 rowsAffected 替代该命令。

现场归档和同步统一协调序号分配。页面获取及解析在写锁外进行，提交短时独占。本阶段只向已结束且现场不再持有的场次写入输出；其他场次拒绝提交且不推进游标。同场合并及现场统计协调由第 4 阶段接入。事件页与元数据页分别原子提交，双游标互不推进。元数据获取游标代表已持久化修订，不代表全部修订已经应用；应用状态独立记录。

解析上下文与事件游标同事务持久化。第 2 阶段用合成上下文验证持久化契约，第 3 阶段定义 adapter 的实际上下文字段及解析版本。

### 区间与进度

使用服务端 next_cursor，而非最后一条成功解析事件或输出数量。未知命令和单条解析失败持久化状态后可推进；页面结构错误、身份不匹配及事务失败不推进。

区间 has_more 未结束前不提交事件扫描进度。继续区间分页保持原事件请求 after 和 limit；range_after 只用于区间分页。metadata_revision 变化从原扫描起点重新读取。扫描边界变化重新组批，禁止混合不同扫描范围的证据。完整区间证据与对应事件进度一起提交。第 2 阶段实现提交前置条件与合成分页验证，生产读取循环在后续阶段接入。

### 迁移与导出

schema 8 到 9 的新增表和 user_version 更新在同一事务完成，不改写事件键、收藏或阅读位置。修正现有初始化写死 schema 8 的语句；版本高于支持范围时拒绝初始化，不降级版本号。失败保留 schema 8，不开放同步写入。

旧数据库升级路径继续有效，终点为 schema 9。档案包支持范围明确为 4、5、6、7、8、9，不随相对版本窗口移动。导出不包含绑定、凭证引用及游标；普通档案包导入不获得来源服务器同步身份。schema 9 不承诺由旧客户端打开。

### 删除及恢复

本地删除档案时，在同事务将对应来源输出标记为本地删除，保留来源收据及同步进度。再次手动或自动同步跳过已删除输出。第 2 阶段不提供重置游标或恢复已删除档案入口。

30 天保留策略作用于服务端原文，不删除客户端已经保存的档案。解绑不删除来源进度；同一 server_id 重新绑定恢复原进度。

| 失败 | 行为 |
| --- | --- |
| 网络中断、503 | 保留提交进度，停止本次操作，允许重试 |
| 401 | 暂停绑定，要求更新令牌 |
| 400 超前游标 | 暂停房间，不自动清零 |
| 404 | 保留档案和进度，核对房间配置 |
| SQLite 锁定 | 沿用有限重试，耗尽后整页失败 |
| 提交前退出 | 下次重读未提交页面 |
| 提交成功但响应丢失 | 读取持久化进度，唯一约束防止重复写入 |
| 单条解析失败 | 保存失败状态，原文仍可用时允许后续重解析 |

### 验收

临时数据库和合成数据覆盖：零/多输出、未知命令、解析失败、重复提交、大于 2^53 的序号及修订号、事务各写入位置故障回滚、现场与同步并发序号分配、独立双游标、区间未读完、修订变化、重启恢复和删除后不复活。

覆盖 schema 8 成功迁移、失败回滚、高版本拒绝，以及 schema 4—8 档案包导入。运行既有客户端和 Rust 测试、构建验证。每项失败明确阻止对应阶段验收，不用服务端测试替代客户端测试。

## 已知边界

- 系统凭证首版支持 Windows；其他平台不能静默使用普通文件存储。
- 第 1、2 阶段不启动真实历史导入，不实现正式设置页面或同步调度。
- 来源身份保证同源幂等，不保证跨端业务去重；itemId 等字段的唯一性范围须在第 4 阶段证明。
- 服务端整场完整性、长时运行及生产实际到期删除尚未验收。
- 共享协议已有独立严格 NodeNext 声明检查限制，详见 shared-protocol-welcome-v1-verification.md；不得将历史报告视为本轮验证结果。
