# 云端历史恢复

> 早期方案，保留原始版本和阶段状态。当前客户端恢复已接入 API v2、协议 0.1.3、恢复契约 0.3；现行行为见[云端记录恢复](../features/cloud-recovery.md)。本文的旧接口、未提交状态及工作树路径不作为当前操作说明。

## 目标

将 BB EventFetcher 服务器已保存的直播记录批量下载到本地，并恢复为当前软件可直接查看和管理的主播、场次与事件。

本功能只补齐“绑定服务器、选择记录、下载、断点续传、转换、写入现有档案、增量更新”这一条路径。恢复后的数据继续使用当前档案、回看、收藏、导出与统计能力，不建立第二套档案。

## 兼容范围

- 服务端 API：`v2`
- 直播协议：`0.1.3`
- Recovery Contract：`0.2`
- 序列化：`bb-json-utf8-v1`

客户端依据协议能力判断兼容性，不锁定服务端程序的精确版本号。服务端缺少上述能力时停止恢复并说明不兼容项。

## 用户流程

1. 在设置中填写服务器地址和访问令牌，验证连接后保存。
2. 输入需要恢复的直播间号并开始任务。当前服务端不提供全服务器房间／场次列表，场次随记录自动恢复。
4. 软件按块下载并持续写入现有档案；中断后可以继续。
5. 完成后可直接从主播档案和回看进入恢复的场次。
6. 再次执行时只处理服务端新增或尚未完成的内容。

## 数据归属

- 非敏感服务器绑定保存在应用数据目录；每个服务器／直播间的完成进度保存在本机设置存储。
- 访问令牌保存在 Windows 凭据管理器，不写入普通配置和诊断包。
- 下载缓存保存在应用缓存目录，可在完成后清理；缓存不是第二份档案。
- 最终主播、场次和事件写入当前 `ArchiveRepository`。

恢复对象使用稳定标识，保证重复执行不会产生重复记录：

- 场次：`cloud-session:{serverId}:{roomId}:{serverSessionId}`
- 事件：`cloud-event:{serverId}:{roomId}:{serverSequence}:{outputIndex}`
- 来源：`cloud-recovery:{serverId}:{roomId}:{cutId}`

## 明确不包含

- 不修改现场录制写入链路。
- 不引入 effective archive、recording archive、generation、layer、projection、activation 或第二套财务统计。
- 不替换现有回看仓库，不改变收藏和导出的语义。
- 不移植验收分支的 FreshReviewPanel、发布/闭包/扁平化/回放架构。
- 不为未来能力预建迁移框架或兼容层。

## 验收标准

- 能连接当前 BB EventFetcher 服务并按直播间创建恢复任务。
- 首次恢复可完成完整下载、转换和写入，恢复过程中内存不会随总数据量持续增长。
- 中断后从已确认的块和写入位置继续，不重复场次和事件。
- 再次运行只恢复新增内容。
- 恢复后的场次可在现有主播档案、回看、筛选、收藏和导出中正常使用。
- 错误提示只说明连接、下载、转换或写入哪个环节失败，以及用户下一步可执行的操作。
