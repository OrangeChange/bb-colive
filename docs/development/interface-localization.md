# 界面文案

## 归属

`src/i18n/zh-CN.json`是软件操作界面的简体中文文案源，条目标识使用英文，按功能和使用语境分组。`src/i18n/index.ts`提供`uiText`及需要分支处理的`UiMessageError`。支持简体中文（默认）、繁体中文、英文和日文。语言入口位于设置 → 通用 → 界面语言，不自动跟随系统。

前端通过`uiText("common.cancel")`等标识读取文案。动态值通过参数传入，如`uiText(key, { name })`。同一条完整提示尽量使用同一条文案；与独立控件、链接共同组成的句子保留既有结构。保持DOM、CSS、配置字段和已有显示结果。

Rust菜单和后台提示以`backend.`开头，与前端共用四份语言资源。`src-tauri/build.rs`将各语言编译为`ui_text!`和`ui_format!`宏，保留Rust格式与编译期检查；后台按当前界面语言选取文本。

LAPLACE事件展示包在构建时将共享标签固化为中文，不携带软件操作界面的语言资源；该输出不参与界面语言切换。

## 边界

事件内部不接入界面语言，包括原生、兼容样式、置顶、回看与样例中的正文、固定文案、身份、金额、时间、倒计时、开奖与名单操作。事件右键菜单和外围工具栏属于操作界面；来自直播事件的系统提醒内容保持原样。

播报模板、试听文字、协议字段、预览分类值、用户数据、主题名称、CSS、自定义变量、导出文件的列名和数据、日志包正文与许可正文保持原样。只翻译对应编辑器、导出窗口、日志操作和许可查看界面的控件文案。

## 逻辑与显示

- 状态、图标、错误分类与筛选使用固定标识，不依赖显示文字。设置图标通过独立名称选择，不再按中文标题查找。
- 需要识别的本地错误使用`UiMessageError.messageKey`。主题文件冲突与目录写入失败通过固定代码跨越Tauri边界，界面按当前语言显示提示。
- CSS诊断的提示／错误类型、音色操作的成功／失败类型与文字分别传递。
- 不把翻译后的标签存成主题ID、配置值或数据字段；不在切换界面语言时改写用户内容。


## 切换与保存

安装器提供简体中文、繁體中文、English、日本語选择。交互安装将所选语言写入软件数据目录的`ui-language.json`；静默安装和自动更新保留原有语言。便携版通过软件内语言设置选择。

语言选择保存于软件数据目录的`ui-language.json`，主窗口、副窗口和原生样式预览启动时读取同一值；独立更新程序通过安装计划继承启动更新时的语言，并开放同一语言读取命令。切换通过Tauri事件同步，不重载页面、不重建连接或清空队列、草稿、筛选与阅读状态。普通浏览器另存本地语言；OBS和外置预览通过既有消息通道接收软件语言，事件内容不变。

组件通过`useUiLanguage`订阅语言变化，渲染时读取`uiText`。模块级选项表使用`localized(() => ...)`就地更新文案，保留表引用与能力注册后的字段；只在包含译文的派生计算中增加语言依赖，不将语言加入连接、播放器、写入器或生命周期副作用。语言选项以各自语言名称显示。

语言是独立偏好，恢复通用外观默认不重置语言。文档`lang`随界面语言更新；界面数字、时间或货币的翻译不改变事件原始值、币种和计算规则。

主题导入使用稳定类定位弹窗，选择器不属于文案。删除保护和裁切说明使用完整句子及命名参数；按钮“显示”与属性分组标题使用不同标识。历史收藏标签属于持久化数据，不随界面语言改写。

## 翻译与维护

运行`npm run translations:export`生成[翻译清单](../translations/ui-translation-list.csv)，带上实际引用位置、变量和格式说明。清单包含当前已接入的三种译文，重新导出保留语言资源中的内容。

新增或修改操作界面时同步维护四份资源与翻译清单。缺失标识回退中文；语言学上有意省略的空字符串保留为空。复用文案前核对含义；同形异义的词保留独立条目。新增事件内容不放入界面资源。

验收检查原文、变量、空格和换行是否保持；按实际操作路径检查正常／窄宽度、明暗模式、异步提示、菜单及独立窗口。事件展示、播报和导出保持原有行为。

数值控件的数字区、单位和调节按钮保留各自空间，译文变长时完整控件换行，不挤压数字。颜色与渐变弹层按窗口边界定位；第三方色板的内部滑块标签和数值说明通过共享本地化钩子同步。验收同时覆盖直接以目标语言启动和中文／英文／日文连续切换，检查输入值、菜单边界与焦点。

选项按可见标题精简，无可见标题的独立筛选保留对象名称。短标签不替代无障碍名称和必要的范围说明。价格配色模式与金额档位下拉中的固定配色使用独立标识；基础档选项和选中值的悬停说明保留下一档边界及无下一档时无上限的规则。

## 开发流程与用语确认

多语言适配是界面改动的完成条件。统一术语见[翻译清单说明](../translations/README.md#统一术语)，布局与交互分别遵循[视觉规范](../specifications/DESIGN.md)和[交互契约](../specifications/UX-CONTRACT.md)。

| 环节 | 要求 |
| --- | --- |
| 设计 | 确定翻译边界和术语，整理标题、按钮、说明、占位文字、悬停提示、无障碍名称，以及加载、空白、成功、失败和禁用状态的完整文案。需要确认的用语在写入界面前确认。 |
| 开发 | 同步维护四份语言资源，复用既定术语、格式化函数和共享控件；完整句子通过命名参数表达，显示文字与逻辑标识分开。组件库的默认英文标签也纳入适配。 |
| 验收 | 按受影响页面核对四种语言、正常宽度与所属面板最窄支持宽度；验证目标语言直接启动和连续切换，输入值、草稿、筛选、阅读位置与焦点保持。字体、配色、浮层或独立窗口有改动时，补验相应字形、深浅模式、层级和输出场景。 |
| 提交 | 文案改动同步更新四份资源、翻译清单与相关测试，运行翻译检查和受影响回归；需要确认的用语未定稿时，明确记录待确认项。 |
| 发布 | 核对本轮多语言验收与用语确认结果，再按已授权的发布流程执行。存在必须确认的用语时，暂停发布，继续完成不依赖该决定的开发和验收。 |

### 需要确认的用语

涉及下列情况时，向产品负责人确认后定稿：

- 新增或更名功能、分类和专业术语。
- 同一概念存在多种合理表达或译法，既有术语和约定不足以确定。
- 删除、覆盖、迁移、收费等提示涉及操作范围或后果，现有已确认表达不能完整覆盖。
- 为适应布局缩短文案，可能丢失含义。
- 翻译会改变已确认的意思或表达风格。

确认稿按功能成组提供实际完整文案、出现位置、四语对照及必要的参数示例，不只列孤立词。尚无可靠译文的项目标明待确认，不以中文占位或猜译作为定稿。文案尚未确定时先完成范围与表达确认，再写入界面；开发中出现新的歧义时补充确认，发布前集中核对剩余待确认项。

### 可以自主完成的用语维护

下列情况可以在既定规则内完成，无需重复确认用语：

- 原样复用已确认的术语和文案。
- 按既定术语表翻译含义明确的常规控件。
- 修正错字、标点、参数、漏译或明显语法问题，保持操作含义不变。
- 整组文案已经确认，后续仅修复布局和显示问题。

构建或翻译检查通过不代表用语已确认，未回复也不代表确认。用语确认与发布授权分别判断：确认措辞不代表授权发布；免于重复确认用语的改动，仍须完成适配与验收，并遵循本次任务的发布授权。

## 界面格式与搜索

`src/i18n/format.ts`统一界面外围的日期、数字与人民币金额格式。日期沿用本机时区和24小时制；简体中文日期保留`YYYY-MM-DD HH:mm`，其他语言的外围日期按本地化格式显示，英文和日文金额使用CNY标明币种。日期时间输入统一由`DateTimeField`提供，输入格式为`YYYY-MM-DD`或`YYYY-MM-DD HH:mm`，日历、星期、翻月提示和时分标签随语言切换。历史元信息、云端恢复、统计与主题日期使用这些函数。主题时间戳序列化、文件名、事件内部和导出数据保持各自原始格式。

设置搜索使用`uiSearchText`收录四种语言的标题与关键词，不临时切换全局语言，不翻译用户查询。结果标签随当前语言显示，定位继续使用稳定的设置ID。

## 构建检查

`npm run translations:check`检查四份资源的标识、有效文本和参数，报告具体语言与标识。已约定省略的“个、位、条、人”量词允许留空，其余空白文案视为缺失。Rust参数同时保留格式说明；前端参数保留名称，允许按语言调整语序。`npm run build`在资源准备和编译前运行检查，避免缺失译文随构建交付。该检查不判断译文含义、界面文字是否全部接入、运行时切换、字形或布局；这些结果须由受影响的组件测试与实际操作验收确认。
