# 文件与图片命名

## 命名规则

- 现行文档按职责命名，使用小写英文和连字符，例如event-visibility.md；日期放在正文中的记录字段。
- React组件沿用PascalCase，模块、配置和测试沿用所在目录的既有规则，不为统一外观更换公共接口名。
- 自有图片使用“主题或功能-部件-状态”的名称；需要区分明暗、缩放时增加light、dark、scale-125等明确后缀。
- 截图按功能归组，名称表达所示部件和状态，不使用final、new、v2等无法解释用途的后缀。历史原件保留原名，靠目录和日期追溯。

## 图片归属

| 类型 | 位置与命名 |
| --- | --- |
| 品牌与程序图标 | src/assets/colive、src-tauri/icons；名称按实际用途或平台尺寸 |
| 原生事件图标 | 所属src/assets目录；等级、门槛等编号有业务含义时保留 |
| 产品预览素材 | public/media按原生或兼容模式分组；稳定路径与预览数据同步维护 |
| 兼容素材 | 保留第三方原始文件名及来源路径，由asset-locations等映射表表达用途 |
| 开发截图与对照图片 | docs/local-history/screenshots，仅本机保留 |
| README 产品展示截图 | docs/images，按展示功能与明暗命名；样例内容明确标注，不包含账号凭据与私有配置 |
| 字体和授权原件 | 保留作者给定名称和授权文件名，不按普通截图重命名 |

## 兼容边界

文件夹名blivechat、openlive、laplace是既有内部标识；公开资源网址、主题ID、存储目录、DOM类名和用户CSS选择器保持稳定。说明文字统一使用BLC原版、BLC开放版、LAPLACE。

移动新增自有资源时同步更新源码导入、CSS、预览数据及清单。不要修改已构建的哈希文件名，也不要只修改dist；生成物由对应脚本重新产生。资源无静态引用不等于无用途，主题CSS和事件数据也会按路径加载图片。
