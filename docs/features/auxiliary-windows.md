# 弹幕窗与收益窗

## 当前行为

两类副窗口是只读事件投影，不创建第二条直播连接。弹幕窗与收益窗复用 `FloatingEventWindow`，保留各自承载分类、合并、到期与布局设置。

副窗口消费主端已经适配、去重和合并的事件及[显示设置](event-display.md)。新增事件分发到窗口与播报；连击更新只更新相关收益窗与播报，不重复当成新增事件。

事件日志复用共享事件行与区域样式配置，公共选择器和参数见[原生事件 DOM 与样式契约](../development/native-event-style-contract.md)。公共区域只包事件日志，拖拽、缩放、窗口表面与礼物特效层保留在外。现有桥接负责主窗口向副窗口及 OBS 投递事件与偏好，各输出独立维护阅读位置。

## 显示容量

副窗口与 OBS 的主事件流默认保留 50 条，范围 1–100。先按现场大类、副窗口承载范围和开关、主题细项、身份及金额筛选，再按合并后的显示项计数；隐藏事件不占容量，也不发送普通事件行。弹幕窗、组合收益窗和各收益分窗分别计算，置顶栏与礼物特效使用独立规则。

缩小容量移除最旧可见项，扩大容量不恢复已淘汰项。关闭分类立即移除对应项，重新开启只接收后续事件。容量淘汰与定时到期使用退出动画；筛选移除与撤回沿用既有呈现。现场会话历史、档案和统计不受影响。手写 CSS 自行隐藏的行不参与自动容量判断。

## 显示策略

### 收益分窗

设置 → 副窗口 → 收益窗的“显示方式”默认“组合窗口”，使用标准设置行与选择器；“开启收益窗”保留为总开关，三个子开关归属“分窗”组。选择“分窗显示”后，收益窗原入口的横向展开栏包含礼物、醒目留言、大航海三个 SVG 子按钮及共享锁定。总关时仍可通过悬停或键盘焦点展开；子按钮点击开关自身窗口，悬停和焦点不改变开关。全部子窗关闭时总开关关闭。总关和最后子窗关闭保留最近非空组合，再打开恢复该组合。

礼物子窗承载普通／盲盒礼物、天选与红包；醒目留言窗承载醒目留言及撤回更新；大航海窗承载购买与荣誉事件。置顶栏使用各窗相同类别范围。所有收益窗共享主连接、房间切换、筛选偏好、置顶候选与锁定；后开子窗继承锁定。首次没有保存选择时，打开分窗默认显示三个子窗；已有选择恢复最近非空组合。模式与选择保存在本机，软件启动仍保持窗口关闭。

组合窗和三个子窗分别记忆几何，模式切换、关闭重开和软件重启不覆盖各自位置与大小。有效的已保存几何继续恢复；只有三个子窗完整符合旧默认方窗尺寸与竖排坐标、且没有自定义标记时，整组更新为紧凑布局。任何一个子窗的位置、大小或自定义标记不同，都保留整组。“恢复收益窗布局”涵盖组合窗和三个子窗；主窗口右侧分区保持原布局。

窗口玻璃使用原生桌面折射，事件与操作层保持独立，不随背景弯折。同一显示器上的玻璃窗口共享桌面捕获；背景静止后停止重复绘制，全部玻璃窗口隐藏时暂停捕获，恢复时刷新背景。关闭窗口或切换纯色、透明时释放玻璃资源。

窗口外观提供“玻璃／纯色／透明”，默认玻璃、窗口明暗跟随软件、玻璃着色18%、纯色不透明度100%、圆角12px。两种材质分别记住强度，范围0%–100%。已有显式底色、纯色不透明度和圆角保留。表面颜色默认按窗口明暗使用软件主题对应的表面色，可自定义，恢复图标返回自动颜色。透明隐藏外壳参数但保留值。弹幕内容有独立的明暗设置，默认跟随软件。定时消失默认关闭、默认10秒，只清理副窗口缓存，不影响主窗口、档案或日志。

“合并相同弹幕”默认关闭，只在副窗口缓存按精确文字／小表情／大表情来源合并，不比较用户名。窗口默认 8 秒，可调 1–60 秒；合并行保留首条用户资料并显示独立 ×N 胶囊。主窗口、回看和礼物合并不受影响。

弹幕窗设置提供弹幕与互动开关，大类同时跟随现场大类；互动细项由当前应用主题控制，不读取现场互动细项。收益窗同样按承载范围跟随现场大类和主题细项。主题大类开关不约束副窗口，OBS 则独立读取主题大类和细项。

开启、锁定与穿透是运行状态，恢复本分类默认不强制打开、关闭、锁定或解锁。收益窗总关时，侧栏和设置中的共享锁定均禁用并保留锁定状态；总开后恢复可用，后开子窗继承锁定。

## 置顶栏

设置 → 事件显示 → 置顶栏，默认关闭、顶部、置顶栏最低礼物金额30元（包含30元，盲盒按开出总价值计算）、最大显示10条、按金额降序；位置、门槛、数量与排序可调整并持久保存，恢复事件显示默认时一起恢复。置顶栏是事件展示能力，用于副窗口和 OBS；当前副窗口仍按已有承载分类分发候选，弹幕窗没有候选时不留置顶栏。

普通付费礼物、醒目留言、大航海购买、天选开始和红包开始可固定；免费礼物、互动及开奖结果不成为卡片。礼物门槛、寿命、显示金额和排序统一使用礼物总价值。普通礼物使用总价值，缺失时用已知单价乘数量；盲盒使用开出单价乘实际数量。价值未知时不成为候选，免费礼物不置顶。盈亏取开出价值减实际支付；支付统计保持原口径。礼物、醒目留言和大航海购买按金额档位确定停留时间，并从首次进入本地置顶候选时开始计时；天选使用原始 `maxTime`，红包使用原始 `waitTime`，两者从事件发生时间计时，缺少可靠时长时不固定。收到对应ID的开奖结果提前移除开始卡片。

先排序再取显示上限。两种排序均将天选放在最前面，多个天选按首条发生时间倒序，同时间按首次接收顺序倒序，优先占用显示名额。其余事件中，红包按实际金额正常参与；金额降序同额按首条发生时间倒序，时间也相同时按首次接收顺序倒序，最新接收的在同价位最前面。金额未知的非天选候选排在已知金额之后。“按时间倒序”不区分金额有无，同样以首条发生时间为准，同时间按首次接收顺序倒序。重复包、连击更新和窗口重开保持首次接收顺序，不把旧卡片当作新卡片。

卡片只显示头像、金额（盲盒含盈亏）和末尾图标；天选显示“天选”，不显示姓名、正文或可见倒计时。大航海购买末尾显示对应身份图片。媒体开关、图标失败回退与样式参数复用现有事件部件。置顶栏位于窗口顶部或底部，保持单行横排；卡片不换行或压缩，超出宽度时可横向滚动但不显示滚动条，普通列表保留独立纵向滚动。

主端在开启功能时维护当前房间的有效候选，包括窗口关闭期间收到的事件；ready 只补发有效固定投影，不补发关闭前的普通列表。付费卡片的首次入列时间、天选与红包的原始发生时间共同决定剩余寿命；重复报文和窗口重开均不续期，礼物合并只更新原卡片内容。普通列表定时消失不影响固定卡片。关闭功能和切房清空主端及副端候选；SC撤回同步副窗口，普通SC行保持原有撤回标记“已撤回”，固定卡片移除。投影仅保存在内存，不产生额外统计、归档、语音或采集。

固定卡片使用200ms滑入／滑出，无论固定栏位于顶部或底部，均从左侧12px滑入、向左侧滑出。退出完成后释放占位，不重置停留时间；切房和关闭功能立即清空。系统开启减少动态效果时不播放。

### 固定时长依据

2026-10-05核对 [LAPLACE当前前端](https://chat.laplace.live/assets/gift-effect-player-B9XQm1oJ.js) 的金额时长函数：正金额各档位与上表一致。本软件的礼物、醒目留言和大航海购买统一按该金额档位计时；天选消费 `max_time`；红包消费 `last_time`，本软件将其保存为 `waitTime`。不能仅凭时长函数相同宣称所有协议、连击或多月购买样本与LAPLACE完全一致。

[B站醒目留言说明](https://live.bilibili.com/blackboard/live-superchat-intro-web.html)说明了官方醒目留言的展示时长；本地置顶栏是独立展示能力，为保持三类付费卡片一致，使用上表金额档位。上表不是已核实的B站官方礼物或大航海固定栏规则。

## 切房与恢复

主端切房发送带房间与连接代次的就绪请求；副窗口发现房间不一致时清理旧内容，应用新房间状态。旧代次通知不能覆盖当前房间，收益窗只接受当前代次确认。收益窗未就绪时每 500ms 重试请求，正确确认或关闭后停止。

关闭重开重新取得当前房间偏好与有效固定候选；普通列表沿用关闭清空策略。副端诊断由主端接收后统一写入。

## 布局

三个收益子窗首次及恢复布局时，使用当前主窗口所在显示器的工作区，读取已打开弹幕窗的实际位置和宽度；弹幕窗关闭时使用保存几何，没有保存几何时预留默认360px弹幕列。优先放在弹幕窗左侧，左侧放不下但右侧足够时改放右侧，按礼物→醒目留言→大航海竖排。外边距10px，窗口间距8px。收益默认宽300px，高度分别为240px、200px、160px；可用空间不足时，宽度缩至最低240px，高度分别以160px、160px、120px为下限，按各窗可收缩高度分配剩余空间。工作区与弹幕窗物理坐标按当前DPI换算为逻辑坐标，支持负坐标显示器。排放只执行一次，之后各窗独立移动缩放并保存几何。恢复后读取原生窗口实际尺寸与位置，保存实际结果并记录布局诊断。

### 已知限制

逻辑工作区至少628px宽、476px高时，可以同时容纳默认弹幕列与三个最小收益子窗及边距。已移动或放大的弹幕窗，两侧至少需有一侧容纳240px收益列、8px间距和外边距；宽度先按实际余量收缩。工作区更窄、更矮或弹幕窗两侧均不足时，保留最小尺寸并将子窗位置收敛于当前工作区，部分窗口可能重叠，不自动跨显示器。工作区本身小于单窗最小尺寸加外边距时，无法同时满足最小尺寸与完整可见。

弹幕窗与组合收益窗默认仍为360×360逻辑像素，原生最小尺寸320×320。组合模式恢复默认位置依据当前显示器工作区：距右侧10px，弹幕窗距顶部10px，组合收益窗紧贴其下方。分窗模式恢复上述收益列。恢复只调整几何，不关闭、不解锁、不清空事件。跨DPI或分辨率不能套用固定物理坐标。

“全部恢复”使用同一工作区与弹幕窗目标位置计算收益列，不依赖跨窗口恢复通知的先后顺序。

顶部／底部追加同步[现场信息流](live-feed.md)，控件位置与箭头随方向变化；定时消失与退出动画使用[事件显示规则](event-display.md#个性化与资源)。

## 实现与验收

入口：`src/windows/FloatingEventWindow.tsx`、`GiftWindow.tsx`；模型：`displayWindowModel.ts`、`giftWindowModel.ts`；桥接：`displayBridge.ts`、`giftBridge.ts`。

验收直播中切房、窗口关闭重开、无新事件时恢复、连击更新、锁定及默认布局、跨不同缩放显示器移动。故障排查联合比较主端投递、接收确认、窗口几何与 render 记录。

穿透、吸附、DPI与关闭刷盘需在实际Windows程序中验证，浏览器组件不能代替原生桌面检查。

## 四版公共行为与特效

四版沿用同一窗口、分类准入、容量、到期与阅读机制，来源适配只负责支持的字段和渲染。内容对齐与最新事件位置取软件公共设置；每个窗口和网页独立阅读，不同步像素滚动位置。切换主题不改变软件行为设置或其他目标绑定。

现场、收益窗与OBS使用独立的礼物特效开关，共用资源匹配、播放器和队列。副窗口特效限组合收益窗与礼物分窗；醒目留言和大航海分窗不播放礼物特效。关闭只清空等待项，换房取消当前播放；事件被主流隐藏、淘汰或置顶到期不删除已经独立触发的播放用途。

OBS网页背景始终透明，事件继续使用所选配色。OBS礼物特效默认关闭，开关位于OBS设置；新开、重连或切换主题不补播历史通知。资源通过同源服务加载，媒体不占事件布局、不阻挡滚动。具体行为见[浏览器输出](browser-output.md)。

## 材质与定位

玻璃采用整窗原生背景模糊与薄着色、细高光，原生圆角与窗口缩放同步；纯色只使用颜色与不透明度。切换纯色或透明时清除原生模糊，透明外壳不保留边框、阴影或高光。窗口明暗与内容明暗分别跟随软件或固定浅色、深色，互不改变对方。原生模糊启用或清除失败会在主窗口提示，不自动重复尝试。

透明窗口确认未锁定时显示细边框与窗名，可拖动窗名和缩放边缘；锁定后移除辅助并穿透鼠标。设置中“开启弹幕窗／开启收益窗”旁的定位图标可让已开启窗口显示三秒辅助，最小化时恢复显示，不抢焦点、不解锁、不移动窗口。分窗使用各自名称，重复定位重新计时。锁定会立即结束尚未完成的定位。

定位不打开关闭的窗口，不清理或重投事件，也不进入OBS浏览器源。窗口捕获可能包含定位辅助，捕获前锁定可移除；捕获是否保留透明通道取决于捕获方式。
