# 连接与登录

## 主播列表与状态

连接栏列出已保存主播并补入回看档案中的主播资料，不限制为最近20位。直播状态通过房间批量接口刷新；顶部主播与列表采用同一直播状态，连接成功不等于已开播。切房、重连和新的直播消息优先于迟到的查询结果。

主播列表读取失败时保留现有文件，不按空列表保存；只有文件不存在时按首次使用处理。状态没有变化时不重写列表，后台保存失败会记录诊断。

移除主播前可选择仅移除列表中的主播卡，或一并删除该主播回看档案；删除档案显示影响范围并确认，受保护的记录不能直接删除。

`room_init` 返回 HTTP 412 时，使用官方 `getRoomBaseInfo` 解析房间，暂停前者请求5分钟。批量状态刷新遇到412同样暂停后再试；不把请求失败写成未开播。

## 当前行为

主窗口恢复本机登录会话，以 B 站 Web 扫码登录获取有效 Cookie。二维码过期会重新生成；接口生成失败会提示检查网络后重试。登录成功后通过 nav 确认登录态，失败不当作已登录。取消登录过程不能让迟到结果覆盖当前界面。

连接初始化读取真实房间号、主播 UID、标题、封面、平台开播时间与房间大航海档位，再建立直播连接。当前房间与连接代次隔离旧请求和旧消息；切房同时更新现场与副窗口，不沿用上个房间资料。

网络失败的幂等 GET 最多自动重试一次，并记录失败阶段。连接失败、登录失效、二维码过期是不同情况；自动重试不能保证上游接口长期不变。没有接入一套可替代失效扫码接口的自动迁移服务。

“开机随系统自启”和“启动后自动连接”独立且默认关闭。自启使用 `--background` 静默托盘启动；自动连接等待会话和主播历史恢复后连接最近主播。没有凭证或主播记录时跳过，普通手动启动显示主窗口。

## 与其他功能的关系

连接和播报不因切换现场、语音、个性播报或回看面板而重建。[档案场次恢复](review-archive.md#场次与记录状态)必须依据房间和可靠平台开播时间，不能仅凭“当前仍在直播”合并。

房间档位和用户身份用于[事件显示](event-display.md)；副窗口的切房与就绪规则见[弹幕窗与礼物窗](auxiliary-windows.md)。

## 实现与验收

主要入口：`src/protocol/login.ts`、`api.ts`、`connection.ts`，`src/stores/connection.ts`。登录 Cookie 只保存在用户数据，不进入源码或诊断包。

验收：扫码成功／过期／取消、无效登录态、正常连接、重连与切房、代理开关后的网络行为、无凭证启动、迟到旧房间响应。网络问题需结合[诊断](diagnostics.md)中的连接编号与端点结果，不只看界面状态。
