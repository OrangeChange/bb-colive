# 回看与档案

## 独立样式设置

回看时间线、事件检索和收藏共用独立回看样式，不继承现场主题或用户自定义CSS。默认基准字号14px、正文500字重；事件元素连续排列，溢出自然换行，头像、图标和时间在行内垂直居中，撤回标记跟随内容。

设置提供基准字号、头像、头像框、身份标记、粉丝牌、等级与排名、图标、统一文字配色和价格梯度。时间始终显示；图标开关覆盖礼物与时间等图标，不控制时间文字。统一文字配色使用深浅模式各自的三级文字色。价格梯度默认关闭，打开后普通礼物、盲盒和醒目留言使用原生默认的金额档位配色，大航海保留固定配色；统一文字配色开启时覆盖文字，梯度背景保留。

天选和红包中奖名单横向排列，空间不足自动换行，条目由头像和用户名组成。头像优先读取事件中奖者资料，缺失时使用已有资料或接口补齐，失败保留默认头像。原始日志不因补齐显示资料而修改。

缺少主播名称的档案先显示“房间＋房间号”，列表加载后后台补齐资料。优先使用本机主播列表，否则请求该房间的主播名称和头像；同一房间在本次运行中只尝试一次，失败保留原显示，下次启动可重试。补全只填空的主播资料，不改变场次、事件和记录时间；已删除的档案不会重新创建。

## 导航与范围

回看是一级工作区，沿用连接栏。设置控制首次进入是否打开当前主播；关闭或没有当前主播时进入档案馆。进入后浏览的主播、场次和条件不随现场连接自动变化，提供查看当前主播／当前场次快捷入口。

面包屑固定目的地：“全部主播”进入档案馆，单场主播名进入该场所属主播档案；真实返回继续沿浏览历史。单场页头保持单行，显示路径、标题、封面、管理档案与导出，不重复堆叠三项状态。场次列表保留状态，进行中用绿色浅底。

主播可独立置顶，偏好只保存在本机，不进入传输包。场次列表复选框和导航按钮保持同级，“全选”只作用于当前已加载且可操作场次，不包含未加载结果。

## 场次与记录状态

| 维度 | 状态 | 含义 |
| --- | --- | --- |
| 直播状态 | 进行中／已结束／状态未知 | 平台直播证据；已结束需可靠下播证据 |
| 记录状态 | 记录中／重连中／已停止 | 本机采集状态，不由直播状态代替 |
| 记录质量 | 待确认／完整／不完整 | 采集边界与已知缺口；已结束不等于完整 |

只在直播中创建／追加场次。恢复以真实房间号与标准化平台开播时间确认同场，沿用场次 ID 并立即落库，不等新事件；无可靠证据或开播时间不同不强行合并。`live_key`／`sub_session_key` 不参与合并判断。恢复查询期间保留待写事件，旧连接请求与旧批次不得覆盖新状态。

启动时遗留记录收口为已停止，未确认直播证据为状态未知；导入的进行中状态不代表本机正在记录。记录停止时间不能替代直播结束时间，没有可靠结束时间时保留空值及“时长未知”。已有被拆开的历史场次不会自动合并。

场次卡、主播摘要、历史事件结果和时间线边界显示本地 `YYYY-MM-DD HH:mm`；底层时间戳、筛选边界与排序不因此改变，分析导出的事件时间精确到秒。

黄色提示合并明确晚加入或采集中断缺口；灰色分别说明停止、标题回退与开播身份不足。缺开播时间本身不产生黄色警告，尚未加载场次时不显示身份缺失。恢复撤去停止提示但保留已知缺口。

提示关闭按场次与原因集合保存在本次窗口会话，相同事实和原因顺序变化不重显，新原因可重新显示；关闭不改变记录事实。写入提示独立于质量：“保存中…”延迟 400ms，“保存失败，正在重试。”立即显示。

## 时间线与检索

回看使用 SQLite 游标分页和虚拟列表，默认倒序排列，可切换顺序排列；切换复用已加载窗口，不为顺序排列加载全量事件。增量录档只在允许跟随时更新阅读位置，跳到最新恢复对应方向跟随。

主播档案的场次列表及事件检索，排序方向文案随字段变化：时间使用“顺序排列／倒序排列”，直播时长、金额和数量使用“升序排列／降序排列”。切换字段不改变已选方向。时间线、收藏和数据导出的时间排序名称保持不变。

运行期间按场次记住阅读位置，再进入自动恢复；重启清空该记忆。上下文定位与跨场摘要进入使用一次性事件目标，不覆盖原阅读锚点。定位后停止跟随，新事件不得推走目标。

主播页分“场次”和“事件检索”，模式及条件按主播保存，排序分别记忆。场次筛标题、开播时间、状态、质量和含收藏；事件检索按场分组、摘要、分页与定位，不把已加载页面当成全量结果。

事件条件包括分类及包含／排除、互动／礼物细分、关键词与同时／任一满足、用户身份、主播粉丝牌、礼物单件／本条累计区间、收藏和时间。关键词用户字段包含用户名及通用昵称；普通事件搜索不包含收藏备注或标签。快捷条件“不看互动”“只看收益”，预设支持新增、重命名和删除。

回看分类全选只调整一级集合，保留细分和包含／排除模式；切模式反选集合以保持结果。细分集合只约束有对应细分的事件，不误隐藏其他一级类型。

查看上下文退出关键词、用户、金额、收藏和时间条件，保留主分类、细分和包含／排除，再定位原事件。用户筛选提供退出入口。回看只合并礼物，不合并弹幕，不继承现场阈值、分类开关或只显示大航海进房。

录档更新只刷新相关房间查询，其他房间不取消在途分页；收藏／整理／导入／删除重载首屏并重置分页，录档保留已加载分组。旧任务不能覆盖新结果、错误或加载状态。

## 写入、管理与传输

标准事件先于现场合并和筛选写入 SQLite，相邻批次合并 200ms，显式刷盘、传输和退出立即排空。恢复与追加的序号及数量以数据库已提交值为准，同场失败批次维持顺序，其他场可继续提交。

管理支持全库、主播、场次及日期范围传输、容量／健康统计和手动清理。保留时长可全局或按主播设置，但不是后台自动删除。删除先预览主播／场次／事件／收藏数，再独立确认；记录中／重连中受保护，已停止可确认删除，不依赖直播或质量标签。删除普通档案级联收藏关系和阅读位置。

档案 JSON 传输用于备份／迁移，不是[分析导出](data-export.md)。完整包保存标准事件、元数据、收藏备注／标签、资源 URL 与阅读数据，不带图片二进制、设置、凭证或诊断；旧 schema 4 包仍可导入。本地非空备注优先，标签并集。

[云端记录恢复](cloud-recovery.md)按直播间从 BB Event Fetcher 下载完整或增量记录，转换后写入同一档案库。它不是档案 JSON 导入，不改变现场录档和回看读取路径。

导入按相同 sessionId 且 owner／room 一致匹配；新事件加入、完全相同跳过、不同仅累计冲突。没有跨源身份匹配、字段级合并或逐项冲突审阅。

## 封面

连接房间信息优先 `room_info.user_cover`，兼容 `cover`，保存到 `cover_url`。场次列表和单场页显示固定 16:9 缩略图，可点击预览；缺失／失败固定占位。重连沿用同场封面，切房不继承；导入本地非空值优先。历史外部补全未接入。
