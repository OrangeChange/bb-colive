# 云端记录恢复

云端记录恢复用于把 BB EventFetcher 保存的直播记录下载到本机，并写入现有回看档案。服务器连接位于“设置 → 回看 → 云端记录服务”；已连接后，可在主播档案右上角直接恢复当前主播。

## 对接基线

当前核对的 BB EventFetcher 主分支源码版本为 **0.7.15**，客户端按接口能力判断兼容，不将服务端程序版本与 BB CoLive 版本绑定。

| 项目 | 当前约定 |
| --- | --- |
| 服务端源码 | 0.7.15，提交 `751461124309577de451b447209826c2d8ba3ce2` |
| 历史恢复 API | v2，信息入口 `/api/v2/info` |
| 直播协议包 | 0.1.3 |
| 恢复契约 | 0.3 |
| 序列化 | `bb-json-utf8-v1` |
| 采集管理、账号与资源 | 继续使用 `/api/v1`，与恢复 v2 同时存在 |

0.5.x 的原始分页接口及 0.6.x 的恢复契约 0.2 不能替代当前恢复接口。后续服务端升级仍须满足表中的能力约定；不能只因服务端版本更高就判定兼容。

## 连接

填写服务器地址和身份码后，客户端检查 API v2、直播协议 0.1.3、恢复契约 0.3 和 `bb-json-utf8-v1`。服务端程序版本可以独立升级，只要上述能力保持兼容。

服务器地址和能力信息保存在应用数据目录；身份码只保存在 Windows 凭据管理器。界面、普通配置和诊断记录不保存身份码。

## 恢复

在主播档案中点击“从云端恢复”后，选择全部场次、指定场次或与指定时间相交的场次。弹幕和互动事件可分别排除；被排除的内容不进入服务端恢复对象，也不会下载。礼物、醒目留言、大航海、场次资料和记录质量始终恢复。客户端读取恢复对象并转换成当前事件模型，再写入现有主播、场次和事件表。回看、筛选、收藏和导出继续使用原档案功能，没有第二套档案库。

同一服务器和直播间首次执行完整恢复，完成后保存服务端进度；再次执行只读取新增记录。重复执行使用稳定事件标识，不产生重复事件。写入失败时不推进完成进度，重试从原进度继续。同一条服务端记录包含多项事件时，恢复进度会记录到具体事件，暂停或失败后不会漏写剩余内容。暂停会停止当前任务并保留进度；继续恢复时重新核对尚未完成的范围。取消恢复会停止任务，删除本次任务新增的记录并清除当前直播间的恢复进度，不影响任务开始前已有的档案。

服务端仍有记录等待场次归属时，软件恢复已经确认的连续范围，但不保存本次服务端完成进度；后续再次恢复时从原边界核对并补写。新的明确归属会同步移动既有事件、收藏和搜索索引；归属暂未确定时保留已归档内容。仅标题、结束状态或完整度发生变化时也会更新场次。服务端增量进度过期后，软件自动重新建立完整进度，稳定事件标识避免重复写入。

下载对象保存在本机临时缓存中；恢复成功、暂停或失败后释放本次任务使用的缓存。转换按连续数据流读取，事件分批写入；归属修订每批最多处理 256 条事件，历史资料按需读取并限制驻留量，避免恢复规模直接转化为前端内存占用。

服务端按直播间分页提供场次列表，并在创建恢复任务时固定本次范围。选择性恢复使用完整任务，不推进“全部场次”的增量进度；只有全部场次恢复会在后续继续读取新增记录。同一时间只运行一个恢复任务，切换回看页面不会中断任务。

## 云端采集管理

“设置 → 回看 → 云端记录服务”显示服务状态、B站账号、采集房间和数据保留设置。本地已经登录 B 站且具备刷新令牌时，可将本地登录态同步到服务器；凭据由 Rust 直接读取并发送，网页界面不接触 Cookie 或刷新令牌。服务器账号与本地账号不同时必须明确确认替换，也可以保留服务器扫码登录。服务器保存配对的刷新令牌后可定期检查并续期；旧的仅 Cookie 账号仍可验证和采集，但需要重新扫码或同步本地登录态才能补齐自动续期能力。

采集房间支持开始、停止和重新开始；停止采集不删除历史记录。数据保留先预览受影响的场次和事件，再确认更新；留空表示永久保留。

## 服务端更新与客户端结果

| 服务端版本 | 更新内容 | 客户端使用方式 |
| --- | --- | --- |
| 0.7.0 | 选择性恢复、服务端过滤弹幕和互动、登录态与配对的刷新令牌同步、账号自动续期检查 | 在恢复窗口选择范围与内容；在云端记录服务中管理登录态 |
| 0.7.3—0.7.6 | 按可靠快照补齐场次标题、分区、开播时间与主播资料；改善资料查询和回填对采集的影响 | 再次恢复可取得场次资料修订，不要求同时出现新事件 |
| 0.7.7—0.7.9 | 依据明确的 `PREPARING` 结束证据保存或补齐结束时间，优化历史结束边界查询 | 回看使用恢复结果中的结束时间；没有可靠边界时继续显示未知，不按最后事件时间补造 |
| 0.7.1、0.7.2、0.7.10—0.7.15 | 缩小恢复预检读取范围，将大规模派生与容量计算放在受保护的构建阶段，批量读取场次事实；恢复连接中断时回滚并隔离失败任务 | 大房间恢复使用相同契约；客户端继续展示准备、下载和写入状态，不因服务端优化改写本地事件 |

服务端一致性冻结仍限制为五秒，默认构建期限为三百秒；实际限额随服务信息和任务返回。超时、资源不足或任务失败不能报告为恢复完成。服务端升级、历史资料回填及索引维护由服务端独立执行：从 0.6.x 升至 0.7.0 有显式结构升级，0.7.4 还涉及资料查询索引，不能将整个 0.7 系列一概视为只换镜像。

## 状态与错误

窗口右下角显示恢复进度，展开后依次显示准备记录、下载、写入档案和整理档案。恢复中可以暂停或取消；暂停后可以继续恢复，也可以取消并撤销本次新增记录。取消前需要确认。连接失败时检查地址与网络；身份码失效时重新保存；协议不兼容时先升级客户端或服务器。恢复完成后刷新现有主播档案，可直接进入场次回看。

## 实现边界

恢复复用 `ArchiveRepository`、当前协议适配器和现有统计重算。采集服务独立部署，提供 [BB EventFetcher](https://github.com/OrangeChange/BB-Event-Fetcher) 对应的恢复接口与契约。

## 版本与验收边界

版本基线日期为 2026-11-25，服务端实现依据为上述主分支源码及 0.7.0—0.7.15 发布说明。实例运行版本以服务器实际返回的信息为准；源码版本、镜像发布、生产部署和真实恢复验收分别维护。

客户端保留来源身份及服务端场次归属，尚不提供本地实时记录与云端记录的完整跨源身份匹配、字段级合并和冲突审阅。采集期间未收到的事件、已过保留期且未保存到本机的记录，不能通过恢复补造；质量标记和快照缺失应保留原义。
