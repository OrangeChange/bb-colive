# 数据导出

## 入口与范围

主播档案和单场页提供“导出数据”，场次列表提供“导出所选”。范围包含当前场次、已选场次、主播全部或日期筛选场次、事件检索结果；完整读取 Repository 分页，不只导出已加载页面。读取前刷档案，在读取阶段使用档案传输互斥，再投影和序列化。

只导出五类：弹幕、互动、礼物（普通、盲盒、红包）、醒目留言、大航海普通行为。里程碑、天选／中奖明细、系统及技术事件不混入统计文件。

## 格式与排序

| 格式 | 文件结构 |
| --- | --- |
| Excel | 一个 xlsx，固定 summary、danmaku、interaction、gift、superchat、guard 六张表 |
| CSV | 一个分类直接 CSV，多分类 ZIP，只含所选分类 CSV；不附 summary、manifest 或 README |
| JSON | 单一对象含 scope、sessions、summary、events，适合 AI 或程序分析，不使用 JSONL |

Excel／CSV 默认顺序排列，可选择倒序排列；选择独立于回看阅读方向。JSON 固定按时间顺序。同时间使用事件序号与稳定事件键确定顺序。

## 列与金额

公共列：场次ID、事件时间、用户UID、用户名、粉丝牌、荣耀等级、大航海身份。资料使用事件捕获值，不在导出时请求补全；事件时间精确到秒。

| 分类 | 公共列之后的列 |
| --- | --- |
| 弹幕 | 内容（结构化回复对象并入文本，与渲染一致） |
| 互动 | 内容（统一互动文案，不另设互动类型） |
| 礼物 | 礼物类型、礼物名称、数量、礼物价值、实际支付金额、盲盒名称 |
| 醒目留言 | 内容、金额 |
| 大航海 | 动作、时长、金额 |

礼物数量包含连击，不另导出连击数。普通与盲盒的礼物价值统一按实际礼物价值，盲盒实际支付为购买本体金额；价值不等于平台结算净收入。红包只保留支付金额，其他礼物项目为空，不导出中奖展开内容。

支付可信增量相加、可信累计替换，V2 候选总额不能直接作为可信支付。未知 Excel／CSV 留空、JSON 为 null，零保持零。同一连击只统计一个逻辑事件。

筛选结果先筛选再合并，可能只含部分累计进度，不能把累计数量解释为筛选时间内新增消费。汇总基于最终导出行，与三种格式口径一致。

## summary

每场一个信息与统计块，不把所有指标挤成一行。场次信息含 ID、主播、标题、开始／结束时间、时长、直播状态、记录状态、记录质量和导出事件数。时长为 `hh:mm:ss`，没有可靠结束时间保留未知。

统计列：统计项、弹幕、互动、普通礼物、盲盒、红包、醒目留言、舰长、提督、总督。行：事件数、独立用户数、数量、礼物价值、金额。不适用留空，分类存在未知金额时金额合计为空，不把部分金额当总额。

## 文件名与边界

文件名由主播、范围、必要时间和单 CSV 分类组成。时间为两位年份 `YYMMDD-HHmm`。单场完整导出使用开播时间，筛选、已选若干场或全部场次补导出时间，例如 `主播_筛选结果_261003-1500.xlsx`；CSV ZIP 内使用 danmaku.csv 等固定分类名。

数据导出用于查看和统计，不是可恢复的档案备份；[档案传输](review-archive.md#写入管理与传输)另行保留内部结构。导出不带原始协议、凭据、图片地址和内部去重字段。

主题颜色、价格梯度、头像与事件图标显隐不改变导出数据；可视化预览不是导出来源。导出仍按所选范围查询档案中的事件事实。

## 实现与验收

入口：`ReviewDataExportDialog.tsx`、`archiveDataExport.ts`、`archiveDataExportFormats.ts`，原生写入 `write_archive_export_bytes`。

验收三格式行数与公共值、分类错配、连击／盲盒／红包金额、未知与零、summary 多行、顺序与倒序、筛选跨场范围、文件名和导出取消／失败。核对实际生成文件，不只检查内存对象。
